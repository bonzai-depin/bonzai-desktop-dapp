# Roleplay relationships and scene quests

Roleplay tracks belong to a companion, not a scene. Scene setup can continue any saved track or create a named zero-heart track without deleting another one. Chat session IDs retain their existing four segments and append the track ID as a fifth segment. Older sessions retain their original IDs and use a stable legacy journal for that companion. Saved-session labels include the track name.

The six heart thresholds are 20, 50, 90, 140, 200 and 280 bond points. Each scene has six sequential quests: arrival, discovery, complication, perspective/trust, resolution and reflection. Bundled scene activities and narrative hooks seed useful quests immediately; “Personalize story” uses the local roleplay LLM to adapt the chapter before its first exchange. It never downloads a separate quest model or invokes media generation.

Successful foreground exchanges are recorded in the journal. The local LLM assesses the active objective after at least two unused exchanges. Completion must include exact evidence from both the user and character. A deterministic reducer verifies those quotes, sequential eligibility and event uniqueness before awarding 15 bond points and 10 story coins. Model-supplied reward values are ignored. Unrelated chat, failed generation and autonomous away messages do not earn points. Semantic assessment remains model-dependent; “Check progress” retries it. Failure does not replace the generated chat response.

Activities unlock with the relationship, including scene-specific activities, shared stories, keepsakes and revisiting memories. They open dialogue opportunities rather than granting points on click. Gifts use fictional story coins only (30 initial coins, quest rewards thereafter); inventory must be purchased before giving. Up to two different gifts per scene grant 1 point, or 3 when matching explicit profile interests. This shop has no wallet or payment integration. Hearts describe trust, never automatic romance or consent.

`src/services/roleplayJourney.js` owns the reducer, validation, rewards and persistence. `RelationshipJourney.vue` owns the journal UI and local model assessment. `RoleplayChat.vue` supplies story context and records successful exchanges. Story context replaces the older inferred relationship-level prompt and is preserved for away-mode narration. Track-specific memories do not use cross-track companion recall.

Journals persist in the existing local store under `roleplayJourneysV1` (localStorage fallback for web). Writes are serialized, corrupt journals are not silently overwritten, and chat deletion does not delete the relationship. Session exports include the relevant journal; full exports include all journals. Import validates journals and preserves existing tracks with the same ID. No journal is published automatically.

Run `npm run test:roleplay`. Browser checks require a local Vite server and `BONZAI_UI_URL`, e.g. `http://127.0.0.1:5188`. Tests cover evidence, duplicate rewards, inventory, track isolation, persistence, responsive layouts and UI error states; they mock story inference and do not measure narrative quality of a live model.

Design references: [Persona 3 Reload](https://persona.atlus.com/p3r/index.html?lang=enbuy) (shared activities and bonds), [Persona 5 Royal](https://persona.atlus.com/p5r/) (trust and Confidants), and [Persona 4 Golden social-link events](https://gamefaqs.gamespot.com/xbox-series-x/370653-persona-4-golden/faqs/81937/social-links-rank-up-events-base-values-and-responses). BonzAI uses original scenes, a six-heart scale and persistent tracks rather than copying Persona's plots or calendar.
