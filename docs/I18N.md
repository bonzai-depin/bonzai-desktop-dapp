# BonzAI Desktop internationalization

BonzAI Desktop ships the same seven languages as BonzAI Web:

- English (`en`)
- Simplified Chinese (`zh`)
- Korean (`ko`)
- Japanese (`ja`)
- Spanish (`es`)
- French (`fr`)
- Russian (`ru`)

The selected language is stored locally under `bonzai.locale`. The app also
uses the operating-system language on first launch and updates the document
language for assistive technology.

## Adding interface copy

New or actively maintained screens should use explicit keys:

```vue
<h1>{{ $t('create.imageTitle') }}</h1>
```

Inside `<script setup>`, use the injected service:

```js
import { useI18n } from '../i18n/index.js'

const i18n = useI18n()
const label = computed(() => i18n.t('common.save'))
```

Add the key to every locale in `src/i18n/messages.js` or to a shared feature
catalog in `src/i18n/features.js`. Do not translate model names, wallet
addresses, user prompts, generated content, source code, or stored business
data.

## Legacy screens

`src/i18n/legacy.js` is a migration bridge for existing screens. It translates
only exact phrases found in the checked-in `generated-ui.json` catalog and
explicitly ignores chat messages, generated results, memory content, code, and
editable content. Hand-reviewed terminology in `legacy.js` takes precedence.

Regenerate the static catalog after changing older templates:

```bash
npm run i18n:generate
```

Generation is a development task. The packaged application never contacts a
translation service.

## Formatting and validation

Use `i18n.number()`, `i18n.date()`, and `i18n.relative()` instead of relying on
the machine's implicit locale. Before release, run:

```bash
npm run test:i18n
npm run build:vite
```

The i18n check verifies locale parity and every explicit translation key used
by Vue and JavaScript source files.
